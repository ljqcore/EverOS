# MEMO Vault：MemCell 来源证据与中文候选设计

**日期：**2026-10-23  
**状态：**已获用户确认；实现已完成

## 目标与界面边界

让审核者看清一条 Episode 实际依据哪段聊天生成，并能从关键片段定位到归档聊天中的消息。候选审核与正式记忆库使用同一套来源定义。Episode 和 Profile 候选的自然语言输出统一为中文。

界面只改两处：候选审核中的“打开原对话”弹窗；记忆库详情中的“来源证据”区域。候选列表、现有来源条目与按钮、筛选、确认操作、导入界面和 Memory Pack 界面不改布局或交互。

## 已确认的现状

- 候选抽取把 user/assistant 消息切成 MemCell，每个 MemCell 生成一条 Episode；候选的 `source_message_ids` 是该 MemCell 中消息 ID 的去重集合。超长消息可能先被切成多个文本片段，片段保留相同消息 ID；只靠 ID 不能完全还原模型读到的字符范围。
- `EpisodeExtractor.aextract(cell, sender_id=None)` 和 `ProfileExtractor.aextract(...)` 未传提示语覆盖，使用 EverAlgo 的默认提示语。默认 Episode 提示语要求跟随对话参与者语言，但中英混合时没有确定的选择规则。项目已有 `src/everos/service/memo_vault_candidate_prompts.py`，其中的中文 Episode/Profile 提示语尚未接入当前候选抽取调用。
- Vault 为 MemCell 中的每条消息保存一行 `candidate_evidence`，从候选文本和该消息中挑词语重叠的原文摘录。摘录可能为空；当前“打开原对话”接口把空摘录也当成来源失效，返回 `CANDIDATE_SOURCE_NOT_FOUND`。
- 候选来源弹窗返回整份标准化聊天及 `selected_message_id`，前端给选中消息上色，但不会自动滚动到该位置。来自同一会话的多个来源按钮因此看起来重复。
- 记忆库详情会用正式记忆的当前正文重新计算原文摘录，最多 360 字。它是原消息中的字面片段，不是模型生成的证明。现有词语匹配可能挑出 `v4.` 这样信息量不足的片段。
- 当前本地 Vault 中，用户示例的三条消息属于同一会话、顺序相邻且摘录可在原消息中找到；另有 10 条来源关联的摘录为空。这个事实说明空摘录必须与归档缺失分别处理。

## 统一术语与判定

| 名称 | 定义 | 判定依据 | 不能据此声称 |
|---|---|---|---|
| 原文件来源 | 导入的 ZIP/JSONL 等原始文件仍在该批次的安全归档目录 | 现有判定为安全归档路径内文件存在；文件哈希已存库，但目前不复验 | 候选记忆正确，或已定位具体支持句 |
| 来源证据 | 生成候选时实际输入的 MemCell 片段及其有序来源消息、来源字符范围；旧候选用已保存的关联消息近似还原 | 候选与批次、会话、消息、片段的关系，以及归档内容哈希 | MemCell 中每条消息都支持候选的每个断言 |
| 关键位置 | 在来源片段内按候选/正式记忆正文找到的一处或数处原文字面跨度 | 匹配算法返回的消息 ID、字符范围、匹配方式和质量 | 已由机器完成事实核验 |
| 打开原对话 | 从来源片段跳到归档的完整 user/assistant 聊天，并定位被选中的消息及关键跨度 | 来源关联和归档可用，摘录可以为空 | 展示了 ZIP 中全部 system/tool 事件 |

“有原文件来源”沿用现有标签与判定；若要验证归档内容未变化，需另行增加哈希复验，不能把它当成现有能力。候选侧现有“来源证据”列表继续作为逐消息的片段入口，不改列表界面；打开后展示 MemCell。关键位置只是阅读辅助，既不决定原文件是否存在，也不决定来源证据是否成立。原对话中的“原”指本批次归档的标准化聊天；工具轨迹仍在单独归档中。

## 方案选择

1. **只展示关键词摘录：**改动小，但会遗漏同义改写，也无法呈现 Episode 所依据的完整 MemCell。
2. **只跳转完整会话：**保留上下文，但长会话难以定位，重复按钮的问题仍明显。
3. **MemCell 片段加关键位置，再可跳完整会话（采用）：**先交代候选的真实输入范围，再提供快速阅读线索和完整上下文。候选和记忆库共用同一个来源模型。

关键位置采用可解释的混合检索：先在 MemCell 原文句段中做词语、专名和数字匹配，过滤过短或缺乏信息量的结果；词面召回不足时，如本地语义模型可用，再对整个 MemCell 的原文句段做语义召回与重排。最后返回原文字面跨度，不生成引文。语义能力不可用或置信度不足时仍展示完整 MemCell，并明确标记“未定位关键句”；不影响来源访问或候选审核。

## 数据与服务设计

### 新抽取产生的来源片段

EverOS 候选响应为每个 Episode 增加版本化 `source_segment`：会话 ID、有序片段项、每项的消息 ID 与原消息字符起止位置、片段顺序、输入文本哈希。分段前的长消息拆分逻辑要保留字符偏移，避免多个片段共享同一消息 ID 时错误地把整条消息称为模型输入。Profile 来源可沿用相同结构。

Vault 验证这些跨度确实属于本批次的标准化消息，并持久化片段元数据。已有 `candidate_evidence` 的逐消息关联继续保留，供现有审核与导出引用；新增的片段关系是它们的上层分组，不把关键词摘录或语义分数写进 UMIF。UMIF 已保存原始事件的来源、顺序和哈希，无须修改格式。

旧候选缺少精确字符跨度：按现有 `candidate_evidence` 的消息 ID 和顺序恢复“关联消息片段”，在 API 中标注 `precision=linked_messages`。新候选为 `precision=exact_input`。两种都可打开；界面不把旧数据误称为精确模型输入。

### 共享来源读取

在 Vault 中建立一个共享的来源读取/定位服务，供候选来源接口与记忆库详情调用。统一返回原文件可用性、片段消息及精度、关键位置列表和定位状态。关键位置根据候选草稿或正式记忆的**当前正文**计算，避免审核改写后仍展示旧摘录；可按正文修订号缓存，不能改变原始来源片段。

“打开原对话”只要求候选与消息的关联有效、消息属于批次且原文件可用。`quote` 为空或关键词/语义匹配失败时，照常打开片段和会话。关联不存在、归档文件缺失、内容哈希不符分别给出不同错误与修复提示；不得再用“来源不再匹配”概括空摘录。

确认入库继续要求原文件可用和来源关系有效，人工负责核对记忆内容。机器匹配分数不作为自动确认条件，也不因没有关键位置阻止审核。

## 两处界面变更

### 候选审核：“打开原对话”弹窗

现有来源条目与按钮保留。点击任一按钮后，弹窗首先展示该候选的一个 MemCell 来源片段：按实际输入顺序排列消息，突出所点消息，并在匹配质量足够时标出关键原文。显示片段起止、消息数与“精确输入片段/旧数据关联消息”标识。

弹窗内提供“查看完整归档聊天”，展开后自动滚动到所点消息并高亮；如果存在关键字符跨度，再定位到该跨度。点击同一候选的另一个来源按钮时更新定位目标，而不是让用户再次从整段会话开头寻找。缺少关键位置时显示“未定位关键句，可阅读本片段”，不显示 404。

### 记忆库详情：“来源证据”区域

用同一个来源片段结构显示该正式记忆对应的 MemCell；默认展示按当前正式记忆正文选出的高质量原文位置，并可展开片段中的其他消息。原文件是否存在、片段是否可还原、关键位置是否找到分别标示。当前逐消息字面摘录仍可作为兼容数据读取，但不再把信息量不足的短词当成“关键证据”。记忆库其余信息与操作保持现状。

## 中文输出

接入现有 `EPISODE_PROMPT_ZH` 与 `PROFILE_PROMPT_ZH`，通过抽取器的 `prompt` 参数显式传入。Episode 的标题与正文、Profile 的自然语言字段一律中文；人名、产品名和代码标识符可保留原文，JSON 键保持协议规定的英文。中文约束只用于 MEMO Vault 的候选抽取，不改 EverOS 其他记忆管线。项目内的提示语是运行时实际调用的机制；另写一个 Codex skill 不会自动约束本地 Ollama 抽取。

提示语接入时确认占位符、时间规则和结构化 JSON 与 EverAlgo 当前版本兼容，并用混合语言、纯英文输入及中文输入分别验收。已经保存的候选不自动重写；需要重新抽取的批次应通过明确的重试/重新生成流程产生新版本，不能静默覆盖人工审核结果。

## 实施顺序与验收

1. 建立来源片段合同和旧数据回退读取；用现有批次校验用户举出的三条消息按顺序形成同一片段。
2. 修正来源接口的空摘录误报，并分离“文件存在”“片段可读”“关键位置已定位”三种状态。
3. 实现共享关键位置选择与低质量过滤，候选和记忆库调用同一服务；无本地语义服务时仍能稳定读取片段。
4. 只改两处指定界面：来源弹窗的片段/定位，记忆库详情的片段证据。
5. 接入现有中文提示语，验证 Episode 与 Profile 输出字段为中文。
6. 用用户给出的三条来源、空摘录来源、超长消息拆分、旧候选、改写后入库的记忆做验收；检查所有跳转定位到正确消息，且原文件缺失时状态真实。完整来源和关键位置不得由模型编造。

## 实施记录

- MEMO Vault 当前没有可复用的本地语义检索服务，因此已实现高质量词面匹配；没有足够匹配时，仍展示完整 MemCell，不阻止打开来源或审核。
- 归档状态现在会校验安全归档路径和导入时记录的 SHA-256；缺失、哈希不符和缺少哈希分别返回状态。
