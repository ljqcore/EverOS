# MEMO Vault 上传 GitHub 前手工测试清单

依据 2026-10-23 当前代码整理。以下是待执行的验收用例，不代表已经通过。每行记录：通过 / 失败 / 阻塞 / 不适用；失败时补充截图、请求状态码、后端日志及复现步骤。所有删除、撤销、过期和异常测试使用独立测试空间与测试数据。

## 1. 准备与执行顺序

- [ ] 重启 EverOS 和 MEMO Vault 后端，确保加载最新代码；启动前端、Ollama，确认模型已下载且配置正确。
- [ ] 打开浏览器开发者工具，保留 Console 和 Network 日志；同时保留两套后端日志。
- [ ] 建立“验收测试”空间及一个子空间，用不同的记忆正文区分来源与场景。
- [ ] 准备三类内容：有明确长期偏好、有稳定用户资料、只有一般问答；另准备中文、英文、中英混合、长文本及特殊字符。
- [ ] 先跑 MD → 抽取 → 审核 → 入库 → Memory Pack 下载，再跑 DeepSeek ZIP 同一流程，之后执行其余用例。

## 10. 服务异常、持久性与页面说明

- [ ] Vault API 停止：页面有可理解的连接失败提示，恢复后可继续；不只显示 Unexpected token。
- [ ] EverOS 停止：归档与人工候选的本地操作行为符合预期；抽取、确认、库读取失败时说明清楚，无假成功。
- [ ] Ollama/模型不可用：抽取失败可以定位原因与重试；原文归档仍在。
- [ ] 请求处理中刷新页面：已提交操作状态能查回，不因重试产生重复记忆。
- [ ] 重启前后端：项目、归档、候选、已确认记忆、修正、撤销及删除状态持久保存。
- [ ] 浏览器 Console 无未处理异常；失败请求的 UI 错误能关联 Network 状态码和后端日志。
- [ ] ADP 导出 Beta 显示尚未实现，不把占位页面当作已经通过的功能。
- [ ] 检查来源页“本轮仅开放通用文件”旧文案，与当前已开放 DeepSeek 的实际状态一致性。
- [ ] README 当前存在过时说明，例如 DeepSeek ZIP、候选审核和记忆库范围；发布前更新为实际支持范围。

## 12. 缺陷记录模板与发布判定

每条缺陷记录：用例编号、输入来源/文件名、记忆类型、操作步骤、预期、实际、前后端请求及日志、是否稳定复现、修复后复测结果。不要在公开 issue 中粘贴真实用户对话或密钥。

上传前优先完成：MD 与 DeepSeek 两条完整流程、Profile 真正入库、人工新增两种类型、来源可追溯、Pack 外发限制、修正/撤销/删除排除规则。数据丢失、跨空间串数据、重复入库、错误来源定位和 deny 内容外发属于必须先修复的问题。仅中文文案或布局问题可记录已知限制，但不能将未执行的用例标为通过。
